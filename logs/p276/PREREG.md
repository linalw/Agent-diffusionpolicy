# P276 预注册：把接触段（夹住前）也换成测量

**2026-11-25。** P275 的判决把唯一剩下的项点名了：控制路径剩余真值 **10 980 次读**，
其中 **5 547 = 87 % 在"夹住前"**（`_grasp_carry_place_impl` 3 843 + 接触伺服 `_apply` 1 704）。
本阶段做那个瓶口。

## 0. 为什么这不是"再试一个旋钮"

`tasks._fruit_state(sample)` 已经是**唯一**的估计器注入点，并且

```
est = self.fruit_estimate          # None 出厂
if est is not None: return est()   # 估计器（每观测发布一次，调用时外推）
return spawner.position(sample), spawner.velocity(sample)   # 出厂：逐字节相同
```

所以把夹住前的读点从 `self.spawner.position(sample)` 换成 `self._fruit_state(sample)[0]`，
在**未武装**（`FRUIT_PRIMITIVE_ESTIMATE` 未设）时**取值完全相同**——这是本阶段能用
"accept 459/459 + 一次同格重放逐字节相同"来证明惰性的原因，不需要新的开关。

## 6. 修正（跑之前发现，记录而非重读）

**A1 - `I2` 是一条设计错误的条款。** 预注册写"武装关闭的同格重放必须逐字节相同"，
但**直接回路本来就不可逐字节重放**：它按渲染帧条件化，记录从 P93 起就把这一点写死了
（"the direct loop is not reproducible, so every count is a branch draw"）。
实测：同配置、同种子、`FRUIT_TRUTH_AUDIT` 关的 `R_s913` 读 **10/10**，而带普查的
`C_s913` 读 **9/10**——这是**分支**，不是回归（普查只是纯 Python 计数，且 P275 的
C/TFs 两臂都带它）。

**替代的惰性证明（有效的那一个）**：`scripts/accept.sh` 的脚本行**也走同一个
`_grasp_carry_place_impl`**，而它**逐字节可重放**——武装关闭时 **459 行 / 458 行逐字节相同**
（唯一差异是 P227i 的资产构建行），所以路由在 `fruit_estimate is None` 时是**取值相同**的，
这正是 `_fruit_state` 的文档契约，也是 selfcheck `P276 contact estimate` 那个钉子钉的东西。

**教训（与 P100 A4 / P103 G5 / P269 的 P2 同类）**：把"逐字节"当门槛，只能用在**可重放**
的那条线（脚本行）；**直接/策略行只能用 计数 + 机制 + 同仪器的两臂**。
