build -> consume gaps (the prepared set's own floor budget)
-------------------------------------------------------------
The build fires on the OTHER arm's payload-clear (mid-attempt); its own
consumption is the next slot start, which follows the next boundary pump.

The floor budget (recorded above as ~0.40 m) is
  _dynamic_pick_lead 0.179 + 0.12 * 1.5 + 0.03 = 0.389 m
and the bed's maximum release along is 0.668 m, so a row can drift only
  (0.668 - 0.389) / 0.12 = 2.3 s
before the consumption re-check drops it. EVERY measured gap is longer than
that (the shortest, 2.7 s, is also longer), so the empty builds are not just
"the belt happens to be empty at build time": a stocked belt would read
built>0, kept=0, dropped>0 on this line. A prepared set can only pay if the
build and the consume are inside the same 2.3 s window, i.e. the line needs a
mid-attempt pump (or a boundary-release build) before the lever has room.
