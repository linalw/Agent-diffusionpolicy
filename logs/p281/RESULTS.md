# P281 结果：把腕部相机装到**垫片外侧朝内看**——遮挡 25.3 %→8.7 %，且这是唯一一个机制与结果同向动的杠杆

**2026-11-26。** 承接 P280 的判决（遮挡体是**手**，不是臂），本阶段做"手指挂载"：
相机不再放在下颌后方朝下看，而是放在**一块垫片的外侧面**、**朝内**看，视线穿过两块垫片之间的空隙。

## 1. 几何（全部来自机器人自身状态）

```
span = task._hand_separation(side)      # 实测指间距（Panda 80 mm）
eye  = jaw + (span/2 + 0.012) * x_axis  # 垫片外侧面再外 12 mm
       - task._pad_standoff(True, s) * z_axis   # 降到果子赤道的高度
aim  = eye - 0.050 * x_axis             # 朝内，沿两块垫片之间的空隙
```

**两处必须用"本手的"数，不能用常数**：
* 高度 = `_pad_standoff`（Panda 是 **42 mm**，OpenArm 是 70 mm）。用 70 mm 的常数把视线放到了
  **皮带面上**（第一格 `eye z=1.175`，画面只有皮带和地面）——改成 42 mm 后 `eye z=1.198`，正对果子赤道；
* `FRUIT_WRIST_MOUNT=jaw` 仍是出厂挂载，逐字节不变。

**画面**（`logs/p281/wrist_pad/wrist_left_02.jpg`）：两块垫片在**左右两侧**（不在视线里），
中间一颗青柠**完整可见**，上游还有另一颗。

## 2. 遮挡（同一个普查，`logs/p280/occlusion.py`）

| 安装 | 接近 | 中段 | **合拢** | 遮挡/果子比 p50 | 遮挡 > 半个果子的帧 |
|---|---:|---:|---:|---:|---:|
| 下颌（P280 基线）| 55.6 % | 37.7 % | **25.3 %** | 10.4× | 793/803 (99 %) |
| **垫片外侧** | 24.4 % | 26.0 % | **8.7 %** | **2.67×** | 569/969 (59 %) |
| 下颌 + side 0.09（P280）| 33.5 % | 42.5 % | 42.3 % | 10.9× | 728/728 (100 %) |

**合拢段的遮挡降到 1/3，比例降到 1/4。** 这是 P276 以来第一个**机制项**真正动了的杠杆。

## 3. 腕部精度与可用率（`colour` 隔离，不需要重训）

| 安装 | \|e\| p50 | \|e\| p90 | 接受率 |
|---|---:|---:|---:|
| 下颌（P277 `K`）| 8.6 mm | — | 13 % |
| **垫片外侧** | **5.5 / 7.5 mm** | 40 / 91 mm | **31 % / 27 %** |

精度与可用率**同时**变好（p50 5.5–7.5 mm，接受率 27–31 %，最小 0.5 mm）。

## 4. 放置（0.08，10 连取，两种子）

| 臂 | pooled |
|---|---|
| 全真值（P276 `C`）| **20/20 = 100 %** |
| 无杠杆（P276 `TFs`）| 9/19 = 47.4 % |
| 腕部 `colour` @ 下颌（P277）| 8/20 = 40 % |
| 力优先扫掠（P278）| 7/20 = 35 % |
| 腕部 `learned` @ 下颌（P279）| 11/20 = 55 % |
| **腕部 `colour` @ 垫片外侧** | **12/20 = 60 %**（6/10、6/10）|

**两种子都是 6/10**，是迄今最好的软件杠杆。但对无杠杆的 **p ≈ 0.54**——**仍然不是速率结论**
（n=20，P93）。能说的是：**它是唯一一个"机制 + 精度 + 可用率 + 计数"四项同向的杠杆**。

## 4b. 两张对照图（以及它们暴露的新代价）

`logs/p281/compare/`：

| 图 | 左：下颌挂载 | 右：垫片外侧 |
|---|---|---|
| `side_by_side.jpg`（各自**最好**的一帧）| 机器人挡 **60.7 %**，果子 17 %，青柠只在左下露出一角、还被压暗 | 机器人挡 **0.00 %**，果子 **54 %**，垫片落在画面上下边缘之外 |
| `side_by_side_typical.jpg`（各自**中位**的一帧）| 果子可见（6.2 %）但**一块垫片斜着横穿画面**，机器人 58.3 % | 机器人 **0.00 %**，但果子是**逆光的暗剪影**（3.0 %）|

**所以垫片挂载把"遮挡"换成了"逆光"**：果子夹在两块垫片之间，相机也在两块垫片之间，
两侧都没有直射光，果子在合拢段基本是**暗轮廓**。这与 §3 的 `colour` 结果并不矛盾
（颜色在暗处仍然可分，p50 5.5 mm、接受率 31 %），但它是**同一个安装的下一个代价**，
而且会**直接影响学习式掩码**（P279 的采集帧是下颌视角、照明更亮，OOD 之外又多了一层分布差）。
真机上对应的解法是**垫片间补光**或在暗处提高曝光——都是安装细节，记录在案。

## 5. 一个被这次挂载暴露的真 bug

`prior behind the camera` 这道检查（`p_cam[2] >= -0.03`）本意是给 **`raster`** 把先验投到像面用，
却挡在三维模式之前。垫片挂载下相机是**横着**看的，先验偏 80 mm 时完全可能在像面之后——
**55/211 次测量被它白白拒掉**。现在它只在 `raster` 分支内生效。

## 6. 还没做的

* **分割器要按这个视角重采重训**：`learned` 在垫片视角上 `mask covered 0 px`（训练分布外），
  所以 §3/§4 用的是不需要重训的 `colour`。P279 的采集→训练→部署管线已经现成，
  **一个来回约 35 分钟**，这是下一格的第一件事。
* **相机是虚拟的**：垫片外侧面挂一个 6 cm 的相机在真机上要装配空间（垫片只有 10 mm 厚），
  实际形态可能是"垫片外侧的短支架"或"侧视棱镜"。这一点是硬件，记录在案。
* 速率证书仍需要 P93 的 ~364 次/臂。


## 8. 不声称

* 不声称 60 % 是速率：12/20 对 9/19 是 p≈0.54。
* 不声称真机可装：垫片 10 mm 厚，6 cm 相机要支架（§6）。
