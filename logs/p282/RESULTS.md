# P282 结果：补光把腕部视角救回来了；而**学习式掩码是更好的传感器、却不是更好的单元**

**2026-11-26。** 两件事一起做：owner 要的**补光**，以及 P281 点名的**按垫片视角重采重训**。

## 1. 补光（两旋钮，默认都关）

| 旋钮 | 默认 | 含义 |
|---|---|---|
| `FRUIT_LIGHT_DOME=<mult>` | **1.0 = 出厂**（140 → 140×mult）| 天穹强度 |
| `FRUIT_LIGHT_WRIST=<intensity>` | **0 = 不建灯** | **腕部环光**：SphereLight，**跟着相机走**（真机就是环光）|

`dome×2 + ring 600` 的实测：腕部帧平均亮度 52.03 → **52.81**，**p10 23.35 → 30.29**，
**max 105.5 → 135.8**。**画面从"暗剪影"变成正常曝光**（`logs/p282/lit/frame40.jpg`：
果子清楚、垫片在两侧、带面可见）。

**这是场景改动**：它改变渲染 → 改变策略输入 → **换分支**。所以默认关，且本阶段所有对照
**只在同一套光之内**比较；`accept.sh` 的脚本行没有相机，逐字节不变（§6）。

## 2. 重采重训（垫片视角 + 补光）

| 项 | 值 |
|---|---|
| 采集 | `FRUIT_WRIST_MOUNT=pad` + 补光，12 连取 → **1800 帧**（12/12 放置，数据源）|

## 3. 同光、同种子的 A/B

**A** = `colour`（不需重训）／**B** = `learned`（本视角的模型）。0.08、10 连取、种子 913/914。

| 臂 | 913 | 914 | pooled | \|e\| p50 | **\|e\| p90** | 接受率 | 判定 |
|---|---:|---:|---:|---|---:|---:|---|
| **A** `colour` | 8/10 | 5/10 | **13/20 = 65 %** | 6.8 / 8.6 mm | **81 / 1427 mm** | 35 / 26 % | 19/19 |
| **B** `learned` | 6/10 | 5/10 | **11/20 = 55 %** | **4.5 / 5.6 mm** | **18 / 19 mm** | **50 / 33 %** | 16/16 |

**同一个分裂，第四次出现**：B 是**严格更好的传感器**——p50 更低（4.5 vs 6.8）、
**p90 从 81–1427 mm 降到 18–19 mm**（颜色门有一次 **1.4 m** 的误锁）、接受率高 1.4–1.9 倍
——**但放置少 2 次**（11 对 13，Fisher p ≈ 0.75，平局）。

**失败类也换了**：A 是 `never-grasped 7` + `did not follow 6`；B 是 `never-grasped 8` +
**`fruit fell off the line` 4**（A 一次都没有）。也就是说 B 把一部分失败换成了"果子被扰动后离开产线"。

## 4. 结论

**(a) 补光有效且必要。** 垫片视角在没有补光时是"逆光暗剪影"（P281 §4b），
现在同一台相机给出正常曝光、果子清楚。**腕部环光是这个安装的配套件**，不是可选项。

**(b) 学习式掩码是更好的传感器，不是更好的单元。** 它把颜色门的**误锁尾部**（1.4 m）
消掉了、把接受率提高 1.4–1.9 倍、把 p90 压到 18 mm——**而放置没有变好，失败类还变差**。
这与 P276–P281 的四次结论一致：**接触段的瓶颈不是"看得多准"，而是"看不看得见 / 手在不在那儿"**；
一旦可见性够了，再高的精度不再转化。

**(c) 所以在垫片视角上，部署选 `colour` 而不是 `learned`。** 这是本阶段的可操作结论：
`FRUIT_WRIST=colour FRUIT_WRIST_MOUNT=pad` + 补光 = 13/20 = **65 %**（迄今最好的无真值接触段）。

**诚实的话**：65 % 与 P281 的 60 % **不同光**，按 PREREG 不可比；11 对 13 是平局。
只能说"同一套光下 colour 不比 learned 差，且失败类更干净"。
