## 2. The knob (`FRUIT_RELEASE_OFFSET`, default off)

`src/fruit_sorting/fruits.py`: a 188-line addition, **0 deletions**.

* `FRUIT_RELEASE_OFFSET=1` + `FRUIT_RELEASE_OFFSET_TABLE=<path>`; with the knob on
  and no table the spawner **raises** ("a missing table must not silently no-op").
* The shift is applied **inside `respawn`**, on the value the schedule has already
  drawn: `x_spawn = planned_x − offset(instance)/1000`. The draw, its place in the
  RNG stream and the schedule are untouched (proven: M1b's 65/65 identical planned
  sequence), which is what makes the A/B a comparison of *the same supply draws*.
* **No clamp on the spawn band.** The table's worst-case excursion over
  `U(0.20, 0.36)` is **0.1552..0.3889 m** against a belt span of **0.11–0.57 m**
  (45 mm to the near edge, 181 mm to the far edge); the *run's* actual spawns were
  **0.1642..0.3888 m** (62 releases, M2-O). The band the metric is about is the
  **delivered** one.
* **Scope gate**: patch and bed schedules are skipped and counted
  (`offset_scoped_off`) — a pair abreast 0.085–0.12 m apart must not have its
  separation changed by a ±55 mm per-instance shift (PREREG §2, phase-1 §11). Inside
  that scope every release goes through `respawn`, so the pump's slot, its top-up
  and the `release_next` recycle are all compensated.
* **Signature** `"<species>|<diameter to 0.1 mm>"` (the instance identity the pool
  exposes). A miss is **left uncompensated and counted** (`offset_misses`), never
  silently zeroed; `rescale` (the collector's recycle) changes the signature, so a
  rescaled fruit becomes a counted miss rather than a stale compensation.
* **One banner line** naming the table and the coverage, printed only when active:
  `[offset] release compensation: table=... instances=16/16 offset_mm=−28.9..+44.8`.
* **Unset contract**: no table read, no draw change, no line, no `stats` key (so
  `scripts/172_supply_selftest.py`'s `sorted(stats.items())` comparisons are
  untouched). Proven, not asserted: **M4** (and M2-C with the diag on, 377/377).

Offline check `python3 logs/p50/p2/offset_knob_selftest.py` — **PASS, 0 failures**,
18 checks: the tables parse and cover their pool 16/16, the mode rule reproduces
`+44.80` / `−28.91`, the arithmetic and the no-clamp excursion, the miss and
scope-gate counters, and the unset contract (one call site; the no-table refusal).

## 8. What this does not show

* **Not adopted, and not a rate.** P3's gate fails on a *count* in a *moved
  branch*; nothing here measures a throughput or a success-rate change. If the
  owner wants the compensation evaluated for rate it needs its own pre-registration
  (the adoption path is phase 3: N-per-arm, the reference re-record, the docs).
* **The mode rule is a bound, not a prediction.** It halves the kiwi's error
  (19.65 → 9.8 mm) but the *mode a release takes is not predicted*: the strawberry
  collapsed to one mode, the tomato became bimodal — both are consequences of the
  shifted initial condition, and both stay inside the margin. A longer live probe
  (PREREG's 240 s form) would sharpen the means, not the mode structure.
* **`m1o`'s kiwi idx 13 residual (+18.1 mm) is a condition mismatch, not a table
  error**: the table is built from the *shipped* (wake-loop) condition while the
  isolated probe runs no wake loop (`OFFSET_TABLE.md` §4: the wake moves exactly
  that instance, +53.12 → +35.03).
* **The patch/bed schedules are out of scope by construction** (§2's scope gate):
  the pair-separation question is unmeasured, so a patch/bed use of this knob would
  need its own pre-registration.
* **The direct/policy interface is out of scope.** `rl_env.select_target` reads the
  *delivered* x, so a compensated spawn would benefit it for free — but its A/B is
  its own pre-registration (a P43-style interface change re-baselines every direct
  number). No policy arm was run here; `accept_policy.sh`'s canary uses the
  **fixed** supply with the knob unset, so it is inert by the M4 proof.
* **`demo_2min.sh` was not run**: the entry path it drives is the same default-off
  stream M4 proves byte-identical on a full ten-attempt acceptance, and the motion
  gate it repeats is in `gate_budgets.txt` for all five arms.
