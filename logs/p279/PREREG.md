# P279 预注册：腕部学习式分割器（选项 B）

**2026-11-26。** (a) 力优先闭合已量完：**扫掠找得到接触、但换不到放置**（`S` 7/20 = 35 %，
与腕部 8/20、无杠杆 9/19 同一档）。本阶段做 (b)，而数据给了它一个明确的理由：

在 P277 的彩色格（`K_s913/K_s914`）里，被拒的帧**不是空的**——`px_med` 是
**826 / 3607 / 4436 / 7797 / 9525** 像素，被拒的理由是 `no plausible cluster` 与
`rms 4.3–8.6 mm`。也就是说**果子在画面里，只是和别的东西粘成一个团**（垫片、邻果、带面）。
颜色门分不开它（颜色模型是"这颗果子的平均色"，而垫片是灰、邻果可能同色）；
**一个只输出果子像素的掩码正好治这个**。

## 1. 采集（本 build 的限制决定了顺序）

这个 build **一次只支持一台带标注的相机**（P213）。所以标签只能在**腕部持有标注器**的那一趟采：

```
FRUIT_WRIST_LABELS=<dir>   # 隐式建相机 + 腕部带 instance_id_segmentation
                           # 每次观测存 rgb.npy / depth.npy / mask.npy
```

**这一趟的代价是头部没有掩码**，所以采集趟用**真值目标**（`FRUIT_GOAL_SOURCE=truth`）跑，
不看成功率——它只是数据源。这一点必须写在记录里，不能把采集趟的放置数当性能。

## 2. 训练

`scripts/293_p279_wrist_seg_train.py`：4 通道（RGB + 深度，归一化）→ 160×120 →
小编码/解码（~60 k 参数）→ 1 通道掩码；BCE + Dice；GPU。

**端点：验证集 IoU。** 若 **IoU < 0.60**，判"这个分辨率/数据量下学不出来"，写负结果。

## 3. 部署

`FRUIT_WRIST=learned`：腕部只 RGB-D（无标注器），网络给掩码 → 反投影 → **跳过**颜色门与
连通域（掩码**就是**隔离）→ 同一套真伪门（距离 0.25 m、下颌 0.12 m、直径一致 20 mm）。

## 4. 判决单元

0.08、种子 913/914 × 10 连取，配方 = P276 的 `TFs`，判决臂 `FRUIT_WRIST=learned`。

| 端点 | 读法 | 判决 |
|---|---|---|
| **P1 分割质量** | 验证 IoU | **< 0.60 = 不可用**（写负）|
| **P2 腕部可用率** | `[wrist] ep=... accepted/attempts` | 与 P277 的彩色门（12–16 %）比；**没有提升就不算解决隔离问题** |
| **P3 腕部误差** | `FRUIT_WRIST_DIAG` 的 `\|e\|` | p50 应 ≤ 10 mm（P277 是 6.3–8.6）|
| **P4 放置** | 对 P276 `TFs` 9/19、腕部 colour 8/20、扫掠 7/20 | **报数，不设杠** |

## 5. 证伪

* **F1**：IoU < 0.60 → 学习式方案在这个数据量下不成立；记录"要多少数据/多大模型"再停。
* **F2**：接受率没升 → 拒绝理由是遮挡而不是"没有掩码"，(b) 的前提被推翻。
* **F3**：放置**低于** 7/20 → 掩码把错东西框进来（例如邻果），写成负结果并给掩码的
  质心偏移。

## 6. 不声称

* 不声称采集趟的放置数：那一趟头部没有掩码，是数据源不是性能格。
* 不声称速率：每臂 20 次是一格分支（P93）。
