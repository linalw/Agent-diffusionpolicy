## 3. 机制：不是"抓不住"，是**合拢时的宽度就是错的**

判定行把两端的失败说得很清楚（`span` 是实测的指间距，`force` 是触觉）：

| 格 | 成功腿 | 失败腿 |
|---|---|---|
| 梨（62 mm）| `span 55.3–70.7 mm`，`force 4.6–7.2 N` | **`span 22.6 / 23.8 / 32.0 / 42.9 mm`**，`force 0.00 N` |
| 荔枝（30 mm）| `span 27.4–32.6 mm`，`force 6.5–7.7 N` | **`span 0.0 / 0.0 / 5.3 mm`**，`force 0.00 N` |

闭合的目标宽度是 `deep = pinch_width × 0.98`，而 `pinch_width` 来自**果子的位姿**（估计）。
梨的失败停在 23–43 mm，说明**估计当时报的宽度只有 24–44 mm**；荔枝停在 **0 mm**，
说明**估计当时报的宽度是 0**（`mask covered 0 px`，掩码里没有果子）。

**所以这两端的失败是同一件事**：合拢那一刻**没有一个可信的测量**——不是"力不够"，
也不是"材质滑"，而是**宽度本身错了**。这也解释了为什么 P282 里学习式掩码把 `|e|` 的
p90 从 1427 mm 压到 18 mm、放置却没变好：**最坏的失败根本不是"位置差 20 mm"，是"没有测量"**。

## 4. 由此落下来一个便宜、可测的杠杆（**已定价，未实现**）

**合拢前的宽度合理性门**：`pinch_width` 若与逼近期测到的直径不一致到某个程度
（例如 `< 0.5 × dia_approach` 或 `< 2 × 指垫的机械下限`），**不要合拢**——中止并重瞄/重选。
理由来自本页的表：梨停在 23–43 mm、荔枝停在 0 mm，这两类都是**必然失败**的闭合，
中止它们**不损失任何会成功的尝试**（成功的腿 span 都在果实宽度附近）。
代价只有一次重试的时间（P40 量过：一次失败探针 1.24–1.50 s），
收益是把 `never-grasped` 从"烧掉一整次尝试"变成"烧掉一个探针"。
