# 真值审计：这套链路里哪些信息是"仿真特权"

**2026-11-25。** 回答一个问题：**当前交付的 99.3% 里，有多少用了现实拿不到的真值？**

结论先说：**目标向量与整个接触段都读仿真真值；只有策略看到的图像是真实测量。** 所以
**99.3% 是"目标与接触都由真值喂"的仿真上界，不是可部署数**。真值无关的路径**已经建好并量过**，
但它在接触段被"测量可得性"卡住（不是估计器精度）。

## 1b. "决策层真值无关"**到底**指什么（只覆盖两件事）

P227ad 的"decision layer"是一个**很窄**的定义，不是"策略整条链路"：

| 属于"决策层" | 代码 | 开关 |
|---|---|---|
| ① 策略**条件化的目标向量**（8 维：位置/速度/直径/箱号） | `_begin_pick` / `_observe` 组 goal | `FRUIT_GOAL_SOURCE=perception` |
| ② **交给原语的那一刻**（`t_arrive`、`dx/dy`） | `_fruit_for_trigger`（两处 `should_fire`） | 同上（跟着 ① 走） |

**只有这两件事。**交接之后的一切仍读真值：

| 仍读真值（交接后） | 例子（`tasks.py`） |
|---|---|
| 抓取瞄点 | `grasp_goal = spawner.position(sample) + …` |
| 下降 / 追够的每 tick 参考 | `fruit_now`、`dynamic_v` |
| 闭合跟随与**抓取验证** | `if fruit_z − z_before > 4 mm` |
| 破带起飞 / pluck dwell | `fruit_now`、`fruit_v_now` |
| 伴降（下放到箱底） | `fruit_now` |
| 成功判定 | `pos = spawner.position(sample)` → `placed` |
| 起始位姿对齐 | `spawner.position(sample)[0]`（果子 x） |

**抓后不读真值**：一旦夹住，载荷位姿由 `_gripper_offset` 死算（`rot.T @ (payload − tcp)`）——所以真值依赖**集中在"交接后、夹住前"**，也正好是现实里最难的窗口（相机被手挡住、只有 15–18% 帧可用）。

## 1c. 模型的**目标**是怎么确定的

**目标是一个 8 维向量**：`[xyz, v(3), 直径, 箱号]`（`FRUIT_OBS_GOAL_AUX=1` 时再加带速/带加速度 →
10 维）。**只有一个装配点**：`rl_env._goal_vector(position, velocity, diameter, bin_index)`。

### 出厂（`FRUIT_GOAL_SOURCE=truth`）

* 在**选择那一刻**装配一次：`target["position"] / ["velocity"] / ["diameter"]`（选中那颗果子的仿真状态）
  + `bin_index`（`grade == "A" → 0/左箱`，否则 `1/右箱`；有指令时用指令解析出的目标）；
* 之后**冻结**整个 attempt —— 只有可选的带速两维每 tick 刷新（`_refresh_goal_aux`）。
* **所以模型看到的是"选中时果子在哪"，不是"现在在哪"**。lead 期间果子会走 **0.19 m**，
  这正是 P145 的结论（"模型是对静态目标的定时重放"），也是**外部到达触发**必需的原因：
  模型只负责把臂带到附近，**最后 ~15 cm 由原语追够补**。

### `FRUIT_GOAL_SOURCE=perception`

同样的 8 个数，但来源换成测量：

```
头部 RGB-D ──▶ 实例掩码 + 深度 ──▶ 裁剪球拟合 ──▶ 卡尔曼（CV）──▶ predict_at(now − t)
                                                                  │（_percept_coast_s 封顶）
                                    goal[0:3]/[3:6] ◀─────────────┘
                                    goal[6] = 拟合直径（有则用）
```

* **每个观测 tick 刷新**（不是选一次就冻），且**外推到"现在"**，遮挡期靠滤波器预测；
* 还没拿到第一帧时，用**站台名义位姿 + 上游 0.45 m**（`_goal_vector` 里的 fallback，**不是真值**）；
* 实测：位置 err p50 **1.9–9.5 mm**、速度 **0.124–0.135 vs 0.120**、直径偏小 4–13%。

### 即使是感知模式，目标里**仍有三处真值**

| 漏点 | 代码 | 说明 |
|---|---|---|
| **直径** | `if self._percept_dia is not None: goal[6] = …` | 拟合没给出半径时**回落到选择时的真值直径**（静默的） |
| **箱号** | `bin_index = 0 if grade == "A" else 1`；指令按 `species/size/grade` 匹配 | `grade` 是**仿真抽取的标签**，不是视觉；现实要靠分级器/人工指令 |
| **选哪一颗** | `select_target` 在 `state["position"]/["diameter"]/["grade"]` 上跑 | 选择本身用真值状态。**P275 建了替代**：`FRUIT_SELECT_FROM=percept` 用一帧分割+球拟合生成候选表（身份来自掩码、状态来自拟合），规则不变；无检测时回落真值并在 episode 行打印 `truth_fallbacks=` |

**一句话**：**目标的 6 个测量维（位置/速度）可以真值无关；直径在拟合失败时回落、
箱号来自标签、而"选哪一颗"仍是真值决策。**

## 1d. P275 建成的东西（去真值施工，默认全关）

| 项 | 旋钮 | 默认 | 说明 |
|---|---|---|---|
| **抓取判定** | `FRUIT_GRASP_JUDGE=truth\|force` | `truth`（逐字节不变） | `force`：`Σ触觉力 ≥ 2 N`（窗口 10 tick，允许 1 次低点）**且** `指间距 ≥ 20 mm`；间距项排除"两垫片互夹"（P103 的 `sep_min 0.2 mm / fmax 213 N`）。两处站点都换：探针后的重抓决定 + 计分标签 |
| **判定的匹配 settle** | `FRUIT_GRASP_JUDGE_SETTLE=<n>` | `0` | 传感判定要 `_step_sim`，那**同时是一个 settle**；真值臂拿同样的 tick，A/B 才对得上 |
| **直径不再回落真值** | `FRUIT_GOAL_NOMINAL_DIA` | `0.060` | 感知模式下拟合没给半径时用名义值，而不是静默用调用者传进来的真值直径 |
| **起始位姿 x** | `FRUIT_START_ALIGN_FROM=truth\|percept` | `truth` | `percept` 用末次相机估计的 x；没有帧时用供料带中心 x（不是真值） |
| **选果** | `FRUIT_SELECT_FROM=truth\|percept` | `truth` | 一帧分割+逐实例球拟合生成候选表；三个选择调用点都换；无检测回落真值并计数 |
| **真值债务表** | `FRUIT_TRUTH_AUDIT=1` | 关 | 在 `FruitSpawner.position/velocity` 上按**调用者函数名**计数，每 episode 打印累计表。关时是一次字典判断 |

**判定的计数陷阱（已量）**：0.12 上 传感判定 95 % vs 出厂 75 %——但那是它自带的 10 tick
settle（P262），不是判定的功劳。判定只在**保真度**（逐次 `sensors` vs `truth` 一致率）上评分。

## 1e. 实测：决策层已去真值，代价 10 点；接触段仍在（P275）

**0.08、同配方、两种子 × 10 连取**（`logs/p275b/`，`logs/p275/RESULTS.md`）：

| 臂 | placed |
|---|---|
| 出厂（全真值） | **19/20 = 95 %** |
| **去真值束**（目标+触发+选果+起始位姿+果径+抓取判定） | **17/20 = 85 %** |

**没有被回落掩盖**：选果 `truth_fallbacks=0`（23 帧、87 个检测、0 unmatched），
触发 `source=percept 20 / truth 0`，抓取判定 **18/18 与真值一致、0 假阳性**。

**债务表（按调用者，两格 20 次尝试的累计）**：

| 调用点 | 出厂 | 去真值 |
|---|---:|---:|
| 触发 `_fruit_for_trigger` | 1 309+1 309 | **0** |
| 选择器 `state` | 60+60 | **0** |
| 起始位姿 `_aligned_start` | 9 | **0** |
| `_fruit_state`（估计器注入点） | 1 673+1 673 | **0** |
| **夹住前**：`_grasp_carry_place_impl` + 接触伺服 `_apply` | 3 531+1 309 | **5 547** |
| 抓后：`_carry_leg` + `_place_low` | 2 443+1 428 | **4 507** |
| 评估：`_episode_events` / `_finalize` | 1 459 / 10 | 1 855 / 10 |

**所以"哪里有关"的精确答案是**：**决策层 0，夹住前的执行 5 547 次读（87 % 的控制路径残差），
抓后 4 507 次，评估 1 865 次**。接触段的门槛是**观测可得性**（P227ae：接触期只有 15–18 % 帧可用），
不是估计精度。

## 2. 这对"可部署"意味着什么（三条分开说）

**(a) 决策层已经可以真值无关，且量过代价。**
`FRUIT_GOAL_SOURCE=perception`（目标 + 触发都走估计器）在**接触段仍是真值**的前提下读到
**10/12**，对真值的 **12/12**。这 1–2 次的差就是"把目标换成测量"的代价。

**(b) 接触层真值无关**目前 **2/6**，原因不是估计器，是**接触期帧可用率 15–18%**
（手挡果子/果子太小/被裁边）。所以"现实可用"的下一步不是更好的滤波器，而是**更好的接触期观测**：
腕部视角（被标注器阻塞，P135）、或**力优先的闭合**（`SIM_LIMIT.md` 的硬件路线）。

**(c) 图像通道本身是"真"，但"看不到那一颗"的问题仍在。**
`instance_id_segmentation` 是完美掩码；现实要一个检测器，且 P214 量到**无掩码的替代方案失败**
（44–62 mm）。所以"只差一个检测器"这句话是对的，但要**按 44–62 mm 的误差预算**去设计。

## 3. 因此，对外只能这么说（一句话版本）

> **上界（目标与接触都由真值）：0.08 连续 139/140 = 99.3 %（20 连取）、80/80（40 连取 ×2），
> 4.8–5.1 件/分，周期 9.7 s。**
> **决策层去真值（目标/触发/选果/起始位姿/果径/抓取判定）：19/20 → 17/20 = 85 %**，
> 0 次回落、0 假阳性（P275）。
> **接触段仍未去真值**：它需要的是接触期的观测可得率（15–18 %），不是更好的滤波器。

**不要**把 99.3% 当"可部署率"引用；它是**上界**。可部署率的当前证据是 **10/12（决策层）+ 接触层未解决**。

## 4. 如果要把真值去掉，最便宜的路径（按已量到的证据排序）

| 优先级 | 动作 | 依据 |
|---|---|---|
| 1 | `FRUIT_GOAL_SOURCE=perception` + `FRUIT_PRIMITIVE_ESTIMATE=1` 的**一次完整格**（0.08，≥2 种子 × 20） | P227ad 的 10/12 只在决策层；接触层的 2/6 是单格 |
| 2 | 接触期观测：**腕部视角的标注器问题**（P135 的第二相机阻塞）或**力优先闭合** | P227ae 的 15–18% 帧可用是唯一卡点 |
| 3 | 把起始位姿对齐改成"上次观测的 x"或固定位姿 | 表 1 第 4 行，未单独测 |
| 4 | 出料端计数（替代 `on_output_belt` 的真值判定） | 只影响**评估**，不影响控制 |

**这些都不改 `src/` 的默认**：四条都在已存在的旋钮上，缺的是**格**，不是代码。
