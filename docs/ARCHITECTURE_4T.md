# 4T 架构：Track / Time / Task / Touch

**状态：提案（2026-11-24）。** 本文把 `Papernew/papers` 的 31 篇与这个单元已有的实测
记录对齐，提出一套**能在真实现场跑**的分拣架构。它不是"再调一个策略"，而是把现在
混在一个循环里的四件事拆成四个时钟，并给出一条延迟账本。

判据只有一句：**任何一层如果只有靠仿真真值或"推理时世界静止"才能成立，就不算落地。**

---

## 0. 一句话

> 现实库里，分拣单元的能力不是由"模型多大"决定，而是由**四个独立的时钟**决定：
> 看见（30 Hz）、算准（10 Hz）、决定（2–5 Hz）、抓住（200–1000 Hz）。
> 模型只出现在它真正有信息优势的那一层；**接触由"感觉"决定，不由"看见"决定**。

### 三个结构性缺陷：现状（同一编号，2026-11-25）

1. **"评估时世界是静止的" → 已处理并量化（P228）。** `FRUIT_EVAL_LATENCY=<d>`
   在决策与执行之间推进 `d` 个 tick（sync-hold），`auto` 用实测 `act()` 墙钟换算；
   回路内 **66 ms = 8 mm**（离线台的 26.4 ms 不能引用）。**单元的容忍是 ≤133 ms**：
   再长就超出追够的 200 tick / 200 mm 预算。**结论修正**：这不是"从未测量"，
   而是**已测且被吸收**——但任何"实时"主张都必须报解析出的 `d`。
2. **"时间预算硬编码" → 带速那一半已被证伪（P229/P233）。** `lead` 确实是
   `v·(…)` 而不是常数距离；0.06–0.18 全部 91–92%，**接合天花板 0.2055 m/s**
   由"选择器地板 + 皮带存量 + 30 tick 轮询"决定，**可用天花板由接触段决定**。
   真正该改的是**接触段**（下降时长、闭合时长、追够预算），不是预位预算。
   而且 **P257 证明提速不是吞吐杠杆**：尝试时长与返回时长都与带速无关。
3. **"接触期看不见" → 结论被 P268 改写。** 0.12 的抓取失败**多数没有接触**
   （10 次里 8 次垫子张开、离果子 47–55 mm）——所以补"感觉"补不到它，
   补的是**到达侧**（P109 的窗口）或**更快的 y 轴**。P102 的贴片触觉确有
   **0.17–0.94 s** 的提前量（滑移可见），但 P103 证明"看见≠能转化"。

### 三个结构性缺陷（调参治不好的）

1. **评估时世界是静止的。** 仿真在 `act()` 期间不推进，所以延迟是免费的。
   这正是 Reflex 与 LIBERO-Dynamic 指出的"指标通胀"：真机上推理的 27 ms，
   皮带走了 **3.2 mm**；推理 + 夹爪闭合的 150 ms，走了 **18 mm**。
   我们现在**从未测量过**这件事对成功率的影响。
2. **时间预算是硬编码的。** 查代码后修正本文初稿的一句错话：`_dynamic_pick_lead`
   并**不是**常数距离，它 = `v·(0.40 + t_desc + 0.15) + 0.03`（截断 0.80 m），
   已经按带速换算了；317 次尝试都读到 0.189 m，只因为它们**都在 0.12 m/s**。
   真正硬编码的是**预算里的时间项**：`overhead = 0.40 s`（预位/稳定）、
   `descend_margin = 0.15 s`、`0.03 m` 距离余量，以及 direct 触发器那套
   `0.90 + 0.60 + 距离/0.20` 秒。三个问题随之而来：
   (a) **没有一项装得下实测的决策延迟**（P228：66 ms，而这是 0.12 m/s 下 8 mm、
   0.30 m/s 下 20 mm）；
   (b) 两个消费者（触发器、追够起点）各有一套预算，**互不推导**；
   (c) 预算项是拍出来的，没有对着实测的预位/下降时长校准过。
   带速一变会不会失效，**从未测过**——这就是 Stage 1 的排行榜（第 8 节）。
3. **接触期看不见。** 不是相机不好（能看见时 4.7 mm），是姿态决定的：
   手指挡住果子、果子太小、被画面裁边。补相机没用，**补感觉有用**。

## 3. 架构

```
        皮带 0.12–0.30 m/s，不减速、不停机（现状不变）
   ┌───────────────────────────────────────────────────────────────┐
   │ L1 Track      30 Hz   RGB-D → 3D 质心 / 速度 / 身份 / 类别      │
   └───────────────────────┬───────────────────────────────────────┘
                           │ TargetState{t_obs, p, v, r, cls, cov, id}
   ┌───────────────────────▼───────────────────────────────────────┐
   │ L2 Time       10 Hz   接触帧预测 + 可达性筛选 + slack           │
   └───────────────────────┬───────────────────────────────────────┘
                           │ Intercept{id, t*, p*, feasible, slack}
   ┌───────────────────────▼───────────────────────────────────────┐
   │ L3 Task      2–5 Hz   抓谁 / 顺序 / 哪个箱 / 是否移交           │
   └───────────────────────┬───────────────────────────────────────┘
                           │ Command{id, bin, t*, deadline}
   ┌───────────────────────▼───────────────────────────────────────┐
   │ L4 Approach  30 Hz 决策 / 120 Hz–1 kHz 执行（异步块 + 守卫）    │
   └───────────────────────┬───────────────────────────────────────┘
                           │ CH(grasp) + grasp_committed
   ┌───────────────────────▼───────────────────────────────────────┐
   │ L5 Touch     200–1000 Hz  宽度设定点 w* + 闭合调度 + 滑移判据   │
   └───────────────────────────────────────────────────────────────┘
```

**贯穿约束：每个消息带 `t_obs`，执行器有权作废过期动作。**（第 5 节）

### L1 Track —— 看见（30 Hz）

- **输入**：固定俯视 RGB-D（必需）；腕部 RGB-D（可选）。
- **输出**：每颗果子一个 `TargetState`：
  `{id, p(3), v(3), r, cls, grade, conf, t_obs, cov(6)}`。
- **做**：
  - 深度反投影 + 已知半径球拟合 → 3D 质心（能看见时 p50 4.7 mm，已实测）。
  - 每实例一个 **CV-KF**（位置+速度）；皮带是匀速，过程噪声取小。
  - 遮挡/出视野 **coast**（只预测不更新），协方差增长；超过上限 → 标记 `stale`，L2 拒绝它。
  - 类别/等级用 **轨迹级投票**（最近 K 帧多数），不是单帧。
- **替换**：`_belt_speed_estimate` 的单点读数；`[fire]` 里对果子状态的直接读取。
- **为什么**：KARL 的实测结论是"EKF 层让出视野/急加速仍能工作"；两阶段苹果的结论是
  "决策应在轨迹级做"。我们的 `err 1.9–9.5 mm`、`v 误差 1.7%` 说明**精度不是瓶颈**，
  所以这一层的工作量应花在 **身份与 coasting**，而不是换检测器。
- **失败模式**：多果重叠时 ID 交换 → 用轨迹级投票 + 3D 距离门联；翻滚导致外观突变 →
  用几何（半径/颜色）而不是 ReID。

### L2 Time —— 算准（10 Hz）

- **输入**：`TargetState` 集合。
- **输出**：`Intercept{id, t*, p*, v*, feasible, slack, reason}`。
- **做**：
  1. `T_lead = ttfa_p95 + t_close + t_settle + margin`（第 4 节）。
  2. 候选接触时刻 `t*≥ now + T_lead`，位置 `p* = p + v·(t*−t_obs)`（匀速）；离带后改抛物+滚动。
  3. **可达性筛选**：对 `p*` 做 IK（残差 ≤ 6 mm、关节余量 ≥ 0.05 rad、垫面 ≥ 2 mm）。
     这套判据我们已经在用（`logs/p123/probe.py`、`scripts/174/183`），只是没有接进选择器。
  4. `slack = t* − now − T_lead`；`slack < 0` → `feasible=False`。
- **替换**：`_dynamic_pick_lead()` 的三个时间常数项，以及 direct 触发器的
  `acquisition_window`；两者归到同一个 `T_lead`。
- **为什么**：PAF-Grasp 的核心就是"只预测接触帧 + 可达性筛选"；AHEAD 的解析拦截基线在
  恒速下拿到 86.8%。**这一层不需要学习**，需要的是把常数换成算术。
- **失败模式**：可达性用近似 IK（快）会漏判边界 → 用两级：粗筛（球面可达）+ 精解（只在 `slack` 前三名）。

### L3 Task —— 决定（2–5 Hz）

- **输入**：全部 `Intercept` + 指令 + 箱容量 + 他臂占用。
- **输出**：`Command{id, bin, t*, deadline}` 或 `Handoff{id, reason}`。
- **做**：
  - 候选 = `feasible` ∩ 类别匹配指令 ∩ 目标箱有容量 ∩ 不属于他臂。
  - **滚动时域**：只看未来 K=3–5 个候选，最大化 `slack`（留缓冲），次选最短行程；
    执行一个后立刻重规划。**不追求全局最优**（论文的 DP 是离线最优，在线只需不犯贪心的错）。
  - `slack < 0` 或 `t_arrive < T_lead` → **显式移交**（不是失败）。
- **替换**：`select_target` 的"最近/最上游"贪心；`FRUIT_SKIP_LATE` 保留为它的退化特例。
- **为什么**：传送带 PnP 调度论文证明贪心确定非最优；我们的 `FRUIT_SKIP_LATE` 实测了
  所有权语义（晚火 1/5 vs 有 lead 15/21）。**多臂协作时，"不抓"是一个正解，不是失败。**
- **记账必须三分类**：`placed / failed / not-mine`。我们实测过：两分类会把 38% 的移交
  记成失败，从而把"调度变好"读成"成功率变差"。**这是最容易做出的假指标。**

### L4 Approach —— 接近（30 Hz 决策 / 120 Hz–1 kHz 执行）

- **输入**：2–4 帧图像（含实例 mask）、proprio、**L2 在当前 tick 的预测拦截点**、
  桶化 proprio 历史（K=6–10 × L 步）、带速。
- **输出**：绝对 7 关节目标块 + 指命令（**只是提议**）。
- **做**：
  - **异步块**：块长 H，执行 s，延迟 `d = ceil(τ/Δt)`；执行视野 `[d, d+s)` 必须已定型
    （连续版：hold + 前缀覆盖；将来可换离散头做 inpainting）。**欠载率必须为 0。**
  - **桶化历史**（TEMPO_ACT）：`c_t ∈ R^{K×dq}` 恒长，治"回撤段与接近段画面一样"。
  - **commit 语义**：`grasp_committed` 置位后锁定目标 ID 与 `t*`，只在偏差超阈值时放弃。
- **替换**：单帧 goal + 固定 lead 的接近；`FRUIT_POLICY_TARGET_RATE` 移到执行器（第 5 节）。
- **为什么**：FASTER 的结论是"反应速度 = TTFA，不是推理总时长"；StreamPI 证明多帧几乎免费；
  TEMPO 证明"犹豫/每帧重规划"是主要失败模式。**我们实测模型只占 9–12% 的 tick，
  所以这一层要"小而准"，不是"大而全"。**
- **明确边界**：**策略不决定何时闭合。** 闭合是 L5 的调度 + L2 的时间判据。
  我们的实测支持这条：模型自己扣扳机时 `gap_close` 落在 112–180 mm，而门是 60 mm。

### L5 Touch —— 抓住（200–1000 Hz）

- **输入**：双指力 `F0/F1`、宽度 `w`（或电流）、命令。
- **做**：
  1. `w*` = 每类水果**成功抓取时的张开度中位数**（从示教统计，一次性标定）。
  2. 闭合是**调度**：按 `t_close` 内到达 `w*` 的速率闭合；**单侧强加载 → 暂停闭合**；
     双侧有载且 `w ≤ w*` → 提。
  3. 滑移判据看 **力/宽度的变化率**，不是视觉、也不是补丁位移。
     **这条是提案，不是已验证的做法**：P103 用"补丁位移"触发重夹，结果是
     5 个控制 `cnp` 一个都没救回来、而且**毁掉了 2 次本来会成功的放置**；
     P102 测过那类位移有 2/60 是良性滑动。所以 L5 的滑移反应必须
     **只在力真正塌陷时**动作，且默认关闭，先按 falsifier 测。
  4. 重夹上限 2 次：实测里用满三次探针的 **17/17 次**都根本没合上果子，
     唯一在第二次探针上转化过。
- **替换**：`_close_*` 里的"闭到底 + 力阈值"；`FRUIT_SLIP_REGRIP` 的**位移**触发。
- **为什么**：RDP 的慢-快结构、LeTac 的 `w*`、GraspTune 的调度、High-Bandwidth 的 200 Hz 反射
  ——四篇的共识是**接触必须进独立小环**。我们的实测正好是它的反面证据：把触觉塞进策略
  全部无收益（62.5→58.3、3/3→1/3、0/3），而独立检测器 AUROC 0.937。
- **失败模式**：`w*` 对同种不同大小的果子要分档（用半径分 3 档），否则大果夹不紧。

## 4. 时间预算：把常数换成算术

这是整个架构里唯一需要写死的公式。它替换现在所有"调出来的"提前量。

```
T_lead = ttfa_p95 + t_close + t_settle + margin
lead_distance = v_belt × (t_setup + T_lead)
```

| 项 | 现状 | 目标 | 怎么测 |
|---|---|---|---|
| `ttfa_p95` | 27.3 ms（仿真，DDIM-16） | 真机 60–100 ms | 打点 `t_obs → 第一个被执行的动作` |
| `t_close` | 未标定 | 80–150 ms | 从"发闭合"到"宽度开始变化"的阶跃响应 |
| `t_settle` | 未标定 | ~90 ms | 到 `w*` 且双侧有载的稳定时间 |
| `margin` | — | 50 ms | 一个果径的 1/10 以下的保守余量 |

代入 0.12 m/s：`T_lead ≈ 0.25–0.35 s` → **30–42 mm**；
代入 0.30 m/s：**75–105 mm**。这正是"为什么必须预测而不是追当前位"的定量理由。

**对照（本文初稿在此处写错，已按代码修正）**：`_dynamic_pick_lead` 已经是
`v·(0.40 + t_desc + 0.15) + 0.03`，即**时间预算 × 带速**，不是常数距离。所以新架构
不是"把 0.19 改小"，而是**把预算里的三个时间项换成实测值，并把实测的决策延迟加进去**：

```
今天:  0.40  (拍)  +  t_desc (由下降剖面算出)  +  0.15 (拍)     -> 距离 = v · 和
目标:  t_setup (实测预位) + t_desc + t_settle (实测) + ttfa (实测 66 ms) + margin
```

区别只有一处，但它是本质的：**今天没有任何一项知道自己的真实值**，也不知道模型
要花 66 ms。带速变高时 `v·` 会把误差按比例放大——这就是要扫速度的理由。

**实测（P229，1 个梯子 + 1 次二分，48 集）**：0.06 / 0.12 / 0.18 三档 **11/10/11 of 12**，
失败全是记录里的握持类（4 次 `fruit did not follow the gripper`，38 集之内），
**没有新的失败类**。而 `>= 0.22` 的四档**根本没启动**：

```
RuntimeError: no graspable fruit reached the selection window in 40 feed rounds
```

原因不是预算，是**跑道的宽度**。选择器只在

```
floor(v) = min(v·(0.40 + t_desc + 0.15) + 0.03, 0.80) + 1.5·v + 0.03
depth    = spawn_y − pick_y = 0.68 m
poll     P = 30 tick = 0.25 s          （reset 的喂料环 `range(30)`）
```

满足 `floor(v) ≤ 距离 ≤ depth` 时才能选中一颗果子，即**可选中带宽**
`depth − floor(v)`，存活 `(depth − floor(v))/v` 秒，必须**至少含一次轮询**：

| v | floor | 带宽 | 存活 | 轮询数 |
|---|---|---|---|---|
| 0.06 | 0.226 | 0.454 m | 7.57 s | **30.3** |
| 0.12 | 0.392 | 0.288 m | 2.40 s | **9.6** |
| 0.18 | 0.558 | 0.122 m | 0.68 s | **2.7** |
| 0.20 | 0.613 | 0.067 m | 0.33 s | **1.3** |
| 0.22 | 0.669 | 0.011 m | 0.05 s | **0.2** |
| 0.24 | 0.724 | **−0.044 m** | — | — |

```
v_max = 0.62 / (1.267 + 1.5 + 0.25) = 0.2055 m/s
```

二分验证：**0.20 能起、0.22 起不来**。（本阶段的工作笔记先用"floor 穿越"算出
0.224，**错了一个轮询周期**——带宽必须"宽到能被看见"，不只是"为正"。）

**所以 Stage 1 的结论不是改公式，而是给这个单元两个分开的工程规格**（加长的
2x2 验证把这两条分开了，`logs/p229/RESULTS.md` §9）：

* **接合天花板**（选择器能不能看见一颗合格的果子）= **0.2055 m/s**，式子对斜率
  与截距都验证过（`+0.10 m` 皮带 → 实测 +0.03，预测 +0.0332；4 格中 3 格吻合，
  漏的那格是**保守**方向）。**这个天花板可以被推高，但推高了没用**。
* **可用天花板**（手能不能在接触时够到）= **≈ 0.18–0.20 m/s**：
  0.06/0.12/0.18 是 **11/10/11 of 12**，0.20 掉到 **7/12**，0.22 是 1/3，0.24 是
  **0/6**。**握持先失败，跑道还没用完**——这就是为什么延长皮带一次放置都没换来。
  追踪到的机制（`FRUIT_CARRY_DIAG=1`，0.24）：失败那条 `contacts@onset=0`、
  `force@onset=0.00 N`、`sep_end=0.0 mm` 对一个 40 mm 果子——**夹爪合在空气里**；
  成功那条是两点接触、`force_min 7.88 N`。

出厂 0.12 站在**可用**天花板的 **67%** 处，不是接合天花板的 58%。两个杠杆都是有
价钱的选项，不是免费调参：

* `FRUIT_BELT_UPSTREAM`（P225t，默认 0，延长上游皮带）：`+0.05 → 0.222`、
  `+0.10 → 0.239`、`+0.15 → 0.255 m/s`。**场景改动**（皮带碰撞体变长），
  按记录欠两份参考 + 存储重基线。
* 轮询节拍 `P`（`reset` 喂料环的 30 tick，direct-only）：减半到 15 tick 可把
  `v_max` 抬到 **0.220**。**没有改**——因为 0.22 以上的失败是"选择器自己的地板
  就够不着"，更快的轮询只能修一半（0.24 时带宽已为负，任何节拍都无效）。

**仍然没做的**：预算里装进 P228 的 66 ms 延迟项。0.12 m/s 下它是 8 mm，占
0.29 m 带宽的 **2.7%**——真实但不约束，等包络被推高时再加。

## 5. 延迟账本与安全守卫（防作弊骨架）

### 账本

每个决策都带一个 header：

```text
Decision{t_obs, t_emit, d, s, chunk_len, deadline}
```

执行器（不是策略）负责：

| 规则 | 检查 | 违反时 |
|---|---|---|
| 动作索引 = `t - t_emit` | `index < chunk_len` | **欠载** → 保持上一动作并计数 |
| 动作未过期 | `t <= deadline` | 作废 → 降级（停/撤） |
| 观测不可替换 | 控制只能读 `t_obs` 时刻的估计 | 记违规（`[prim] source=` 已有该机制） |
| 速率/关节/工作空间 | `|Δq| ≤ 5.45 rad/s`、关节限位、包围盒 | 截断并计数 |

**欠载率必须是 0**（LIBERO-Dynamic 实测：K=1/4 时欠载 828/329 每千步，成功率 0%/23.9%；
K=6 时欠载归零、成功率见顶）。这条比"成功率"更能说明异步是否真的成立。

### 守卫放在执行器，不放在策略

P207 实测：把发射目标按 5.45 rad/s 斜坡化后，最大单步 **2.633 → 0.182 rad**、6/6 放置。
这说明**限速是免费的**，而它属于"单元的物理安全属性"，不该由模型学。
同理关节夹紧、工作空间盒、力上限、以及"过期作废"都在执行器。

## 6. 验收协议（这一节是"不作弊"的定义）

任何一项新机制，按下面的顺序读。**顺序错了就会读出假结论。**

| # | 指标 | 怎么读 | 什么使它无效 |
|---|---|---|---|
| 1 | **SR(D) 曲线**，D ∈ {0, 2, 4, 8} 控制步 | 推理期间世界按 RTF 推进 | 只报 D=0 的配置**一律不得采纳** |
| 2 | **TTFA** p50/p95 | 打点实测 | 用"推理总时长"代替 |
| 3 | **欠载率 / 1000 步** | 执行器计数 | 部署 K 上非 0 |
| 4 | **分类 × 带速表**（4 果 × 3 速） | 每格单独报 | 只报总平均（会藏住草莓） |
| 5 | **track-level misbin rate** | 轨迹级投票后的错箱率 | 帧级准确率 |
| 6 | **drop rate**（掉落皮带） | 独立计数 | 混进失败里 |
| 7 | **max normal force**（损伤代理） | 每腿最大法向力 | 只报平均力 |
| 8 | **三分类：placed / failed / not-mine** | 移交是正解 | 两分类（把移交记成失败） |
| 9 | **每腿机制量**（残差、slack、闭合偏移） | 跨配置比这些，不比重试率 | 跨配置比成功率（AGENTS §2） |

**三条"作弊探测器"**（任一触发，该次测量作废）：

1. **世界在推理期间是否推进？** 若 `D=0` 却声称"实时"，无效。
2. **`t_obs` 之后是否还有真值进入控制？** 我们在 `[prim] source=percept|truth` 已经有这个开关；
   统计每腿的真值读取数即可。
3. **评分端点是否等于部署端点？** 我们踩过：`on_output_belt(final)` 在载荷已被传送带带走后
   读到 Fals（P142）。**端点必须在代码里声明，并在日志里打印。**

**每个阶段预注册 falsifier**，与 P92/P93/P109 的现有做法一致（先写判据，再看单元格）。

## 8. 分期（按"每期能独立证伪"排序）

**判据**：若 SR(4) 相对 SR(0) 掉超过 1 次尝试/6，说明**当前所有"实时"结论都偏高**，

**判据**：`residual` 不随带速单调增长；`not-mine` 计数上升而 `failed` 下降。

### Stage 2 —— 接触小环（1 周，零新硬件）

**做**：`contact.py` 的 `w*` 表（从 156 集示教统计每类成功抓取的中位张开度）+ 闭合调度。
**答**：小果类（荔枝/草莓）与 6.9 cm 梨是否改善。
**判据**：`sep@loss - dia`（挤压代理）不恶化，小果类放置数上升。

**判据**：D=4 时 SR 与 D=0 的差 ≤ 1/6。

### Stage 4 —— 硬件侧（需采购/加工）

腕部相机（受 P135 的"第二台标注相机抢 mask"阻塞）或指端 F/T；真机标定 `t_close`、`t_settle`；
**真实损伤测量**（目前仿真没有压痕模型，60 N 的"不压坏"是仿真结论，不是现实结论）。

## 10. 风险与未解

1. **`T_lead` 的 `t_settle` 可能与带速相关**（pid 跟踪一个移动目标）。Stage 1 的扫描就是测它。
2. **轨迹投票会引入 0.1–0.2 s 延迟**（两阶段苹果的代价）。在 0.30 m/s 下就是 30–60 mm，
   必须计入 `T_lead`。**不要把它算进"感知延迟"之外再重复计一次。**
3. **`w*` 部分是"位置等价的力控"**，对可变形水果（草莓）未必等价于力控；Stage 2 要单独看
   草莓格的损伤代理。
4. **单臂 + 双箱的调度空间很小**（14 s 周期、2 个目的地），调度的收益大概率**不是论文的
   10–40%**，而是"消掉晚火与来回跑"。不要按论文倍数承诺。
5. **损伤仍然没有测量手段**：仿真里 60 N 不压坏，现实里 3.6 cm 草莓会。购买力传感器之前，
   任何"安全夹持力"的结论都是仿真结论。

- 它把已有的三条结论**升级成结构**：
  - P135 的"预测门好于速度门" → L2 的拦截点算术；
  - P227ac 的"移交是正解" → L3 的三分类记账；
  - P227ae 的"接触期看不见" → L5 的独立小环。
- 它明确**否证**两件已在记录里但未被当作缺陷的事：**评估的 D=0**（Stage 0）、
  **固定的 `lead` 常数**（Stage 1）。

## 12. 实测状态（P228–P232，单臂 Panda + 两箱 + 学习接近）

这一节是**已测到的工程规格**，供任何接手的人直接引用；每条都指向记录。

### 12.1 速度

| 带速 m/s | 0.06 | **0.08** | 0.12 | 0.18 | 0.20 | 0.22+ |
|---|---|---|---|---|---|---|
| 放置 | 11/12 | **11/12** | 10/12 | 11/12 | **7/12** | **不接合/失败** |

* **接合天花板**（选择器能不能看见合格的果子）= **0.2055 m/s**，由
  `depth(0.68) ÷ (预算 2.767 s + 轮询 0.25 s)` 决定，2×2 验证过（P229）。
* **可用天花板**（手能不能在接触时够到并拿住）= **≈0.18–0.20 m/s**，
  **比接合天花板先到**——所以延长皮带（`FRUIT_BELT_UPSTREAM`）对吞吐**无效**。
* 0.22 以上不是"变难"，是**空抓**：闭合时 `contacts@onset = 0`（P229），
  或闭合抓住了、抬升时丢掉（P230）。

### 12.2 延迟

* 回路内 **66 ms p50 = 8 mm**（0.12 m/s），离线台是 26.4 ms（P228）。
* **单元吸收 ≤133 ms**：块总是迟到，火只是偶尔迟到（`d=16` 时 4/12）；
  因为每次决策重观测，迟到是**常数滞后**而非累积误差，追够有 200 mm 预算。
* **评估必须按 `FRUIT_EVAL_LATENCY=auto` 跑**，`d=0` 报告的是机器没有的延迟。

### 12.3 抗扰动（第一级）

* **±50% 带速波动**（0.04–0.12 @0.5 Hz）→ **11/12**，与恒速同计数（P232）。
* 机制**不是**触发器：它读的是 `encoder_speed` 的**陈旧回显**（P141），
  在波动下 `t_arrive` 可差 **2×**；救回来的是**原语的悬停/下降**（读
  `surface_speed`）。**这是一个待修的真实缺陷**：补偿是一次**等待**，而等待
  花掉的是提前量。

### 12.4 已被实测关闭的杠杆（不要重做）

| 杠杆 | 结论 | 出处 |
|---|---|---|
| 闭合提前量封顶（`FRUIT_CLOSE_LEAD_CAP`） | 前提被证伪：闭合**抓得住** | P230 |
| 抬升随皮带移动（`FRUIT_LIFT_TRACK_BELT`） | 几何不可行：1.6–4.0 s 的抬升要 382–964 mm 的 y 行程 | P231 |
| 延长上游皮带（`FRUIT_BELT_UPSTREAM`） | 抬高的是接合天花板，而握持先失败 | P229 |
| 更快的抬升/放置剖面 | P89/P88/P227r 均为负 | 记录 |

### 12.5 吞吐（P236–P240 实测的块分解，取代本节的旧估算）

单臂 **≈13.5 s/次**，其中 **~10 s 是固定成本（75%）**：

| 块 | 秒 | 性质 |
|---|---|---|
| `place`（转位 + Cartesian） | **3.48** | 常数 |
| `release`（含 0.5 s 释放后采样 + 撤回） | 2.16–2.27 | dwell 已修剪 |
| `grip`（探针/验证） | 1.58 | 常数 |
| **`seat`（追够）** | **0.22 或 1.67** | **唯一双峰** |
| `descent` | 1.5–4.9 | 含等果，不可缩短 |
| `lift` | ~1.2 | P89 测过加速是负 |
| `ramp`（闭合剖面） | **1.10** | 常数 |
| `return` | 0.50 | — |

**`seat` 的 1.44 s 差额已查到根**：追够的退出容差是 **6 mm**，而它在本速下的
稳态误差就是 **6.6–6.7 mm**（= 82 ms 滞后），所以循环**跑到 200 tick 预算**才停，
差 0.6 mm 没过线。**改 lead 无效**（P240：+82 ms 后残差不变，还翻车一次 102 mm），
说明主分量不在带速方向；下一步的仪器是 `[catch]` 行里的 **残差分量 `x= y= z=`**。

**所以"分拣速度"的下一步不是换剖面，而是把那 6.6 mm 的**来源**分清（y 还是 z）。

### 12.6 一句话结论

> 这一代单元的可交付规格是：**0.08–0.18 m/s、≈92% 放置、±50% 带速波动无损失、
> ≈4 件/分**；再往上（0.20+）失败在**握持物理**，出路是硬件（`SIM_LIMIT.md` 的
> 两项制裁：新垫面资产 / 真实夹持力锚）而不是软件。
