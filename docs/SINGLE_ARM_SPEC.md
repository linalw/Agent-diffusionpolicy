# 单臂分拣单元：实测规格与交接清单

**2026-11-25。** 这一页是 P228–P247 的交付面：一台 Franka Panda + 一条皮带 +
两个浅沿料箱，接近由学习策略驱动、接触由脚本原语执行。**每个数字都有日志出处**，
文档末尾写明怎么复现与怎么读。

---

## 1. 单元是什么

```
0.08–0.18 m/s 皮带（动态散料，不停机、不减速）
   └─ 学习策略：接近（约 9–12% 的 tick）
        └─ 脚本原语：追够 → 闭合 → 抬升 → 转位 → 释放（约 90%）
两个料箱：z 底 1.10、沿口 1.13（浅沿，见 §5）
```

**0.12 的杠杆不是周期（P264）**：把这六项提速（周期 11.9 → 9.6 s）带到 0.12 后，失败类别
**与提速前一模一样**（7 握持 + 4 漏抓，对 3 + 2），计数在抽样噪声内（85% n=60 对 72.5% n=40，
p≈0.13）。**握持是 `SIM_LIMIT.md` 的硬件/物理问题**。

**0.12 的"停滞"有两类，判据是量级不是符号（P266 纠正 P265）**：
**慢收敛** 101–187 tick、残差 **8.7–8.9 mm（正常值）**、`y` ±5.8（贴着 6 mm 窗）——**这些会成功**；
**真停滞** 200 tick、残差 **47–55 mm**——失败。**`y` 的正负号不是判据**（正常收敛的残差本来就是
`y≈±5.8`），**47–55 mm 才是**。前者只需要一个不在最后 0.1 mm 上等待的容差；后者需要到达侧
（P109 的窗口）或更快的 y 轴——不是守卫。`FRUIT_CATCH_STALL_TICKS` 守卫因此**不采纳**：它只会
截断那些本来会成功的追赶。

**（P265 的原始表述如下，其"符号"部分已被上式取代）0.12 的抓取失败是"手在果子后方"**：`fruit fell off the line` 只在**被选中的**
果子掉到带下才结束一集，所以它不是漏选/排产，而是**选中的果子没抓住、随带走到底**。`[catch]`
分量给出的签名很干净：**收敛的 20–28 tick、残差 7.8–8.8 mm、`y≈−5.8`（手在下游）**；
**停滞的都是 200 tick 且 `y` 为正（+10.6…+37.6 mm，手在果子后方）**。0.12 下果子每 tick 走
1 mm，30 mm 的落后就是 200 tick 的追赶——正好耗尽预算；0.08 是 0.67 mm/tick，同样的落后能在
预算内追平，所以那一档看不到它。**杠杆是"到达时的手位"**：加重提前量 → 更靠后（本失败），
减轻 → `past_aim` → P109 的双稳态（233–269 mm 飞车，79 次里 5 次）。出厂的 0.15 已在安全侧。

**两条关键读法**：

> **这条线是"臂受限"，不是"线受限"（P257）**：0.08 → 0.12 的尝试时长**都是 11.8–11.9 s**、
> 返回**都是 2.25–2.74 s**，所以提高带速**不增加件/分**（4.26 → 4.10），只增加失败
> （98.6% → 85.0%）。**吞吐杠杆在臂的周期上，不在传送带上。**

* **线的规格按峰值表面速度定，不按均值**（0.18 均值 + 峰值 0.21 = 一条 0.21 的线）。
* 0.08 的 91.7% 与 0.18 的 91.7% 是**同一个平台**；0.20 的 58% 是握持物理开始付费。

## 4. 那条 1.44 s：机制与状态

追够的退出容差是 **6 mm**，而它在 0.08 的稳态误差是 **6.6–6.7 mm**，且**几乎全在 z**
（`x=-0.1 y=+0.5 z=-6.6`）——是重力/可达的静差，控制器不消。于是循环**跑满 200 tick
预算**才退（1.67 s），差 0.6 mm 没过线。

**这个杠杆已经出厂**（P248 功效格 + P249 作用域化）：`FRUIT_CATCH_TOL_AXIS` 在
**direct 车道**未设时默认开启（分轴退出：`|y| ≤ 6 mm`, `|z| ≤ 10 mm`，**指令不动**），
脚本臂/两线/采集器仍是出厂的 3-D 范数退出（`=0` 可关）。

* 追够 200 → **21–42 tick**，`seat` 1.67 → 0.17–0.34 s，**−1.44 s/次**；
* 同一批 11/12 放置；常数 z 前馈（`FRUIT_CATCH_Z_FF`）效果相同但**不占优**（动指令，且有同一飞车率）。

**它为什么成立、以及边界**：因为 0.08 下 `y` 已经 5.2–5.8 mm（在 6 mm 内），循环一直只是被
`z` 卡住。**带速一高，`y` 涨出容差，这个修复就失效**——它是"去掉一个不可达项"，不是"修好循环"。

**功效格（P248，每臂 40 次，2 种子 × 20 集）**：放置 **40/40 对 38/40**（非劣，
+2 是平局，Fisher p = 0.49），追够中位 **200 → 21 tick**（对照 35/40 跑满预算，
处理 0/40），`seat` **1.67 → 0.17 s**，周期 **13.55 → 12.13 s（−1.42 s）**，
飞车在**对照组**（1113.7 mm）而处理组 **0 次**。合并 P243/P247 的 28 次：
**26/28 放置、27/28 在 21–42 tick**。

**它为什么能出厂而不动脚本臂**：`FRUIT_CATCH_TOL_AXIS` 在 direct 车道上按作用域
解析（脚本/两线 = `scope-off`），所以 `accept.sh` 仍 **7/10、`fingerprint: matches`、
459/459 逐字节相同**，**没有参考被重录**。

## 5b. 残余失败的构成（P250 普查，312 集）

| 直径 | 放置 |
|---|---|
| **0–4 cm** | **72/90 = 80.0%** |
| 4–5 cm | 18/20 = 90.0% |
| 5–6 cm | 59/63 = 93.7% |
| 6–7 cm | 132/139 = 95.0% |

**失败集中在一个"体"上，而不是一个尺寸类（P255 纠正）**：317 集里 31 次失败中的 17 次
都是 **同一个抽取**（seed 901 首抽的那颗 2.8 cm 荔枝，43%），其余荔枝实例 **29/29**。
**但把荔枝单独成一池（`FRUIT_SUPPLY_SPECIES=lychee`）连续跑：20/20 = 100%，
其中 2.8 cm 抽到 2 次、两次都放置成功。**

所以下面这张表读作**"在混合池里各尺寸的观测发生率"**，**不可读成尺寸效应**：
同一尺寸换一个池就通过。**一条尺寸桶不是"类"**——要主张按尺寸的限制，先跑该物种的单类池
（10 分钟，能把"这个尺寸"和"这个体"分开）。

**它的失败链已测到**（P251，18 次跑的块分解）：追够残差停在 39–46 mm → `close` 的
1.10 s 斜坡扑在**果子不在垫间**的位置 → 探针失败 → 两次重夹失败 → 丢掉。
判据是 **`grip` 块：通过 1.58 s（10/11）、失败 4.53 s（10/11）**；
**`seat` 不是判据**（有一次通过也跑满 200 tick）。

**物理参数也不解释**（P256，读 `FruitSample` 的 mass/mu）：失败是 8.3 g/mu0.62 与
44.2 g/mu0.53，而通过里既有 9.9 g（更轻）也有 mu 0.49（更滑）——**质量、摩擦、尺寸、物种
都不分开**。并且 31 次失败里只有 17 次是那颗荔枝，其余 14 次散在 kiwi/草莓/桃/橙/番茄/苹果，
所以它是**集中**而不是"类"。**一条物理参数只有在失败与通过零重叠时才算机制。**

**软件侧的作动器已逐个测掉**：退出判据（通过也跑满预算）、时间预算（加倍更差）、
IK 增益（0.5/1.0/2.0 = 3/2/2 of 6，平局）、关节限位（`limit_margin` +0.43…+1.42）、
奇异（`sigma_min` 0.153–0.214）、起点偏移（通过的一次从 50.8 mm 起）。剩下的是
`logs/p42/SIM_LIMIT.md` 的硬件清单（新垫面资产 / 真实夹持力锚）或给最小类改工位/瞄点。

**"1 m 飞车"不是手臂**（P251）：`z=+1274 mm` 是果子掉到皮带下 1.27 m，循环还在追它——
是**丢失载荷**，不是臂的失控。所以那些离群是失败的**后果**，不是原因。

**读法**：不要引用单一池的合计成功率，先看尺寸构成。

## 6. 开放项（如实列出）

1. **首尝试离群**：每轮至多 1 次（第一个 episode），0–1 次放置，**没有任何已测变量能解释**
   （诊断 / cycle 报告 / 分量字段 / 初始化 / 偏置均已证伪）。**不要给它编速率。**
2. **垂直积分 / 重力前馈**：静差的原则性修法（不偏置指令），控制器层，未建。
3. **更快的带速**：≥0.22 的失败是握持物理，出路是硬件（`logs/p42/SIM_LIMIT.md` 的两项制裁：
   新垫面资产 / 真实夹持力锚）或能随带移动的手。

   接触层 2/6——腕部视角被标注器问题阻塞（P135）。

## 7. 怎么复现

```bash
# 单臂脚本单元（96%）
SKIP_SELFCHECK=1 scripts/283_single_arm_gate.sh 6 5

# 单臂学习车道（91.7%，按集）
SKIP_SELFCHECK=1 scripts/284_single_arm_policy_gate.sh 6 901 0.60

# 部署形态（连续，无按集重置）——一条命令
SKIP_SELFCHECK=1 scripts/290_single_arm_continuous.sh 20 905 0.08

# 带速阶梯 / 扰动 / 分轴退出
scripts/288_speed_ladder.sh                      # SPEEDS / SEEDS / EPISODES / OUT
FRUIT_BELT_WAVE_AMP=0.06 scripts/288_speed_ladder.sh
FRUIT_CATCH_TOL_AXIS=1 FRUIT_CYCLE_REPORT=1 FRUIT_TRACK_DIAG=1 scripts/288_speed_ladder.sh

# 门禁
scripts/selfcheck.sh; scripts/accept.sh
```

**0.12 的残余是节拍不是抓取**（P253 §2）：`fruit fell off the line` 的分类读数是
`pos=(+0.273,-0.897,+0.906) held=False`——**果子从站台旁经过未被抓、随带走到线尾掉落**，
不是回收槽也不是掉件。所以 0.12 的 5 次失败是 **2 次漏抓（节拍）+ 3 次握持**，
尺寸覆盖 3.4–6.7 cm **两端**，**不是** 2.8 cm 那一类。下一个杠杆是**集间返回**（263 tick）
对果子到达，而不是小果抓取。

**`FRUIT_SKIP_LATE` 是拓扑相关的**（P252 §6）：**多臂线**用 `0.5`（真的移交给另一条臂）；
**单臂单元**在 0.12 以上必须用 `0`——单臂没有"别的手臂"可移交，一次移交就是一次**丢弃**。
实测 0.12 连续：开 55%（4 次移交），关 **75%**。0.08 下它 20 次里从不开火，所以基线不受影响。

**一条本段提炼的规则（P237/P254/P263 三次同形）**：**settle 不是可以删掉的等待，它是下一段腿
花掉的"起步信用"**——删掉它，代价会在下一段出现（P263：blend −0.25、Cartesian +0.19，
合计 −0.06，总周期平局）。**要量一对，不要量一段。**

**读法**（这几条比数字重要）：

* 6 集是**一次抽样**，不是速率；跨配置比成功数没有意义，比**每腿机制量**。
* **诊断格不是速率**：同一配置加一行逐 tick 打印，6 集计数可差两次。
* 带速格的"不接合"是**边界**，不是 0%。
* 延迟必须按 `FRUIT_EVAL_LATENCY=auto` 评估；`d=0` 报的是机器没有的延迟。
* **一集有两行 `[rl] episode N:`**：第一行是**宣告**（`... lychee grade=A d=2.8cm bin=0 arm=left y=+0.613
  presentation=direct`），第二行是**结果**（带 `success= grasped= placed=`）。所以
  `grep -c "rl] episode"` 会把一集**数成两集**——统计时按 `success=` 过滤（本页所有数字都这么做）。
